## 业务背景（练习时代入这个设定）

你是上海办公室的数据分析师。销售团队在中国各港口做铁矿石现货销售：船到港后，矿石卸在港口堆场，按批次卖给钢厂和贸易商。

- **定价逻辑**：以普氏指数 IODEX 62% Fe（美元/干吨）为基准，按矿种品位升贴水，块矿有额外溢价，再按美元汇率和水分折算成人民币湿吨含税价
- **干吨 vs 湿吨**：`干吨 = 湿吨 × (1 − 水分%)`，结算按湿吨、计价按干吨，这是这个行业最容易算错的地方
- **管理层关心的**：卖了多少吨、均价多少、相对指数是溢价还是贴水、哪个港口走货快、库存压了多少

> 🎯 **埋了一个练习点**：`02_fact_sales.csv` 里有 5 条记录的 `customer_id` 是 `997 / 998 / 999`，在客户维度表里**查不到**。
> 用 `INNER JOIN` 会悄悄丢掉它们（金额对不上），用 `LEFT JOIN` 会留下一堆 `NULL`。
> **这就是真实工作里"报表数字对不上"最常见的原因。** 你要能自己发现它，并写出检查它的 SQL。
