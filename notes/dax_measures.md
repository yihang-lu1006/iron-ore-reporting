## 二、写 DAX 的硬规则

### 1. 引用列 vs 引用度量值

```DAX
fact_sales[amount_rmb]     -- 引用「列」：一定写表名
[Total Amount]             -- 引用「度量值」：只写名字，不写表名
```
一眼能分清哪个是列、哪个是度量值。

### 2. 除法一律用 `DIVIDE`，不用 `/`

分母为 0 或空值时，`/` 报错或返回无穷大，`DIVIDE` 安全返回空值。

### 3. 比率永远是度量值，不是计算列

计算列逐行先算好比率，汇总时变成「平均数的平均数」。
正确做法：**先把可加的列各自 `SUM`，再相除**（= 加权平均）。

> 实证：逐行单价的简单平均 2025 年是 891.33，加权是 890.41。每吨差 1 元 × 1,165 万吨 ≈ **1,500 万元**，两种算法都不报错。

### 4. 先定义基础度量值，再引用它们

`Avg Price (weighted)` 引用 `[Total Amount]` 和 `[Total Tonnes]`，而不是各写一遍 `SUM`。
好处：**口径只定义一次**。金额口径要改（含不含税），只改 `Total Amount` 一处。
（同 Excel 的 `$E$1` 参数格、Power Query 的 `DataFolder` 参数。）

### 5. `COUNTROWS` vs `COUNT(列)`

- `COUNTROWS(表)` 数**行数**，= SQL 的 `COUNT(*)`
- `COUNT(列)` 数该列**非空**的个数

数「成交笔数」本意就是数行 → 用 `COUNTROWS`。

### 6. 数客户、建关系一律用 `customer_key`

孤儿 999 / 998 / 997 已在 Power Query 里归到 **-1**。
用 `customer_id` 会把三个孤儿当成三个不同的客户。
`customer_id` 只在**排查孤儿**时用。

---

### 7. 迭代器里用列，不用度量值（11-19）

`SUMX` / `FILTER` / `AVERAGEX` 这类迭代器的第二个参数里，**能用列就用列**：

```DAX
SUMX ( fact_sales, fact_sales[amount_rmb] * 0.01 )    -- 好
SUMX ( fact_sales, [Total Amount] * 0.01 )            -- 结果对，但慢一个数量级
```

写度量值会**逐行触发上下文转换**（`CALCULATE` 的第二个作用，自动发生）。1,843 行就是 1,843 次。到岗后排查慢报表，这是第一个怀疑对象。

### 8. 判断空只用 `ISBLANK`，不用 `= BLANK()`（11-20）

```DAX
NOT ISBLANK ( dim_customer[credit_days] )   -- 好
dim_customer[credit_days] <> BLANK()        -- 会把真正录了 0 的行也排除
```

因为 DAX 里 **`BLANK() = 0` 和 `BLANK() = ""` 都成立**。
> 和 SQL 正好拧着：SQL 里 `col = NULL` 永远不成立（NULL 谁都不等于，连自己都不等于）；DAX 里 BLANK 等于 0。**换工具要重装这条。**

| SQL | DAX |
|---|---|
| `x IS NULL` | `ISBLANK ( 表[列] )` |
| `x IS NOT NULL` | `NOT ISBLANK ( 表[列] )` |
| `x <> y` | `x <> y`（**DAX 没有 `!=`**） |

### 9. 名字必须带口径（11-17 / 11-20）

`Amount % of Total` 里的 "Total" 指当年还是全部？看不出来 → 该叫 `Amount % of Year`。

- 后缀写口径：`(weighted)` `(terms only)` `(served)` `(identified)` `(identified, strict)`。
- **绝对不要写版本号**：`Customer Count 2` / `_new` / `_v2` 三个月后自己都分不清。
- 同一个指标的不同口径**可以并存**，但名字必须让人不看公式就知道差别；最终只留一个，其余删掉——否则同事在字段列表里会随手拖错。

## 三、两种上下文（模块 4 的地基）

> **一个度量值 = 一条写了聚合、但没写 `WHERE` 和 `GROUP BY` 的 SQL。那两样由用户点哪里来补。**

### 筛选上下文（filter context）

**= 这个数字被计算的那一刻，当前生效的所有筛选条件的集合。**
度量值**每个格子算一遍**，每一遍的筛选上下文都不同。

它从**外面**来，度量值被动接收：

| 来源 | 例子 |
|---|---|
| 视觉对象的行 / 列 | 表格的每一行、柱子 |
| 切片器 | 用户选了「2026 年」 |
| 筛选器窗格 | 报表级 / 页面级 / 视觉对象级 |
| **RLS** | `华东区` 角色 ← **用户看不见，在最外层** |
| **`CALCULATE`** | 公式自己改写的 |

**⭐ 分组这件事本身就是筛选上下文。** `SUMMARIZECOLUMNS(dim_customer[customer_type], …)` 会为每个值建立一个筛选上下文，再在每个里面算一遍度量值。所以度量值不需要 `CALCULATE` 就会「分组」。

**筛选上下文沿关系箭头传播**（单向：维度 → 事实）。所以模型建错 → 所有度量值一起错。

### 行上下文（row context）

**= 当前正在处理的是哪一行。** 计算列逐行算，所以一定有行上下文。

**⭐ 行上下文只存在于正在被遍历的那张表上，不会沿关系传播。**

实证（建在 `dim_customer` 上的计算列）：

```DAX
test_row = fact_sales[amount_rmb]
-- ❌ 报错：A single value for column 'amount_rmb' cannot be determined
-- 遍历的是 dim_customer，不知道 fact_sales 的哪一行
```

### ⭐ 上下文转换（context transition）

**行上下文不会自动变成筛选上下文。** 对比（都建在 `dim_customer` 上）：

```DAX
test_sum  = SUM ( fact_sales[amount_rmb] )
-- 每行都是 27,106,012,244.79（有行上下文，但筛选上下文是空的）

test_calc = CALCULATE ( SUM ( fact_sales[amount_rmb] ) )
-- 每行是该客户自己的金额：华东特钢集团 2,197,988,584.16
-- CALCULATE 里一个筛选条件都没写，结果却完全不同
```

> **`CALCULATE` 把当前的行上下文，变成等价的筛选上下文。**
> 有了筛选上下文，就能沿关系流到 `fact_sales`。

**所以 `CALCULATE` 有两个作用，第二个隐蔽得多：**

| 作用 | 什么时候发生 |
|---|---|
| ① 按你写的条件**改写**筛选上下文 | 你写了筛选参数时 |
| ② **上下文转换**：行上下文 → 筛选上下文 | **只要有行上下文就自动发生，哪怕一个参数都没写** |

### 三者对照

| | 行上下文 | 筛选上下文 | 结果 |
|---|---|---|---|
| 计算列 `test_sum` | 有 | **空** | 每行 27.1bn |
| 计算列 `test_calc` | 有 | `CALCULATE` 转换出来的 | 每行该客户的金额 |
| **度量值**放在分组查询里 | **没有** | **有**（分组给的） | 每组一个数 ✅ |

## 四、⭐ `CALCULATE` 的筛选规则

> **同一列的筛选被<u>替换</u>，其他列的筛选被<u>保留</u>。**
> `CALCULATE` 只管它**点名**的那一列，没点名的一律不动。

实证：`Steel Amount` 按 `customer_type` 分三行时，**贸易商那一行显示的也是钢厂金额**（16,463,184,095.41）——原条件 `customer_type = 贸易商` 被替换掉了。

而同时按年份分组时，`Steel Amount` 在 2025 / 2026 两行会是**不同**的数——年份在另一列，没被动过。

SQL 类比：
```sql
-- 用户点出来的
WHERE customer_type = '贸易商' AND year = 2025
-- CALCULATE(…, customer_type = "钢厂") 之后
WHERE customer_type = '钢厂'   AND year = 2025
```

> RLS 与它的关系：**RLS 先把数据收窄，`CALCULATE` 只能在剩下的范围里改筛选**，改不回被 RLS 挡掉的部分。

## 五、函数速查（筛选器 / 层级感知 / 时间智能 / 迭代器）

### `ALL` 的清除半径 —— 点名越具体，清得越少

| 写法 | 清掉谁的筛选 |
|---|---|
| `ALL ( dim_customer[customer_type] )` | **只有这一列**。region、customer_name 照样生效 |
| `ALL ( dim_customer )` | 这一整张维度表的所有列 |
| `ALL ( fact_sales )` | 事实表 **+ 所有通过关系挂上去的维度表**（客户 / 矿种 / 港口 / **日期**全清）← 比直觉大得多 |

⚠️ 用 `ALL(fact_sales)` 做占比分母**连年份都会清掉**：用户选了 2026，分母仍是两年总额。
⚠️ `ALL(表[列])` 点名的那一列**就是要清的目标**，不是"除了它以外"——"除了"是 `ALLEXCEPT`。

### 六个函数对照

| 函数 | 做什么 | 什么时候用 / 别用 |
|---|---|---|
| `ALL` | 清除筛选，返回全量 | 要一个**永远不变**的分母 |
| `ALLSELECTED` | 只清**视觉对象内部**的筛选（表格行列），**保留外部**（切片器、筛选器窗格） | 要"占用户当前选择的比例"。三者里最难，涉及影子筛选上下文，边界情况多 |
| `ALLEXCEPT ( 表, 保留列… )` | `ALL` 的逆：**保留**点名的列，清掉其余 | 要一个**绝对**的分母。`ALL(一列)` 是**相对**的——加一层 `customer_type`，同一个度量值从 14.00% 变 27.81%，不报错 |
| `FILTER ( 表, 条件 )` | 返回满足条件的行；**唯一能写跨列条件的方式** | 第一个参数：数该随切片器变 → `fact_sales`；是基准 / 分母 → `ALL(fact_sales)`。能在维度表上直接筛就别用 `FILTER` 绕事实表 |
| `VALUES ( 表[列] )` | 当前筛选下这一列**还看得见**的值（`ALL` 的反义词） | 返回**单列表**不是值，通常被 `COUNTROWS` 包起来。⚠️ 对维度表用它时，事实表侧的筛选（年份、销售员）逆不回来 |
| `RELATED ( 维度表[列] )` | 从事实表这一行查对应维度行的一列 | **只能在行上下文里**；只能多 → 一。反方向是 `RELATEDTABLE`，返回一张表 |

### ⭐ 两条方向规则

```
筛选流动：  dim_customer ──►  fact_sales      顺箭头，缩小范围
RELATED：   dim_customer ◄──  fact_sales      逆箭头，查一个值
```

方向相反但都成立，因为干的不是同一件事：**筛选**要缩小范围（一个客户对应多笔单，缩小是确定的）；**`RELATED`** 要查一个值（`*:1` 保证一笔成交只对应一个客户，答案唯一）。

**口诀：筛选往下游流，取值往上游查。**

`RELATED` 的三个对照：SQL = 关系已声明好的 `LEFT JOIN` 取对面一列（不用写 `ON`）；Power Query = Merge（区别：Merge 把列**存**下来，`RELATED` 算的时候**临时查**）；Excel = 跨表 XLOOKUP。

**什么时候用哪个**：

- 要拿来**分组 / 切片 / 放筛选器** → 直接用维度表的列，**别复制到事实表**（那是在制造两个会打架的真相）。
- 只在**计算内部逐行**需要 → 度量值里 `RELATED`。
- 真要在事实表里有这一列 → 优先在 **Power Query 里 Merge**，不写 DAX 计算列。

### `SUMX`：为什么需要迭代器

**DAX 的 `SUM` 只接受一列**，`SUM(a * b)` 写不出来。SQL 一句话的事，DAX 拆成"逐行算 + 汇总"两步：

```DAX
SUMX ( 要遍历的表 , 对每一行算什么 )
```

**踩坑**：在 `SUMX(` 的**第一个参数**里打不出 `RELATED`，自动补全只给 `RELATEDTABLE`。两个原因：① 该位置要的是**表**，`RELATED` 返回值；② **行上下文是 `SUMX` 遍历时才产生的，只存在于第二个参数里**。

> ⭐ **自动补全"不提示"本身就是诊断信息**（第二次出现，第一次是 `CALCULATE` 第一参数不能放裸列名）。看到列表里没有想要的函数，先问：我在第几个参数上？这里要表还是值？有没有行上下文？

### 层级感知三件套（11-22）

| 函数 | 问的问题 | 返回 |
|---|---|---|
| `HASONEVALUE ( 列 )` | 这一列**是不是只剩一个值** | TRUE / FALSE |
| `SELECTEDVALUE ( 列, 兜底 )` | 只剩一个就给我那个值 ≡ `IF(HASONEVALUE, VALUES, 兜底)` | 值 |
| `ISINSCOPE ( 列 )` | 这一列**是不是当前行的分组依据** | TRUE / FALSE |

| 场景 | `HASONEVALUE` | `ISINSCOPE` |
|---|---|---|
| 该列在行区分组 | True | True |
| 小计行，组里有 8 个值 | False | False |
| **小计行，组里只剩 1 个值** | **True** ✗ | **False** ✅ |
| **该列不在行区，但切片器只选了一个** | **True** ✗ | **False** ✅ |

> **判断层级用 `ISINSCOPE`，判断唯一值 / 取值用 `HASONEVALUE` / `SELECTEDVALUE`。**
> 反过来也会翻车：**Card 没有分组层级，`ISINSCOPE` 在它上面永远 FALSE**——动态标题只能用 `SELECTEDVALUE`。
> `SELECTEDVALUE` 是第一个让度量值**主动读取用户选择**的函数（此前都只是被动接收）。两类用途：动态标题；**假设分析**（参数表 + `SELECTEDVALUE` 把滑块值喂进公式）。
> ⚠️ 兜底文案的含义是"**不止一个值**"，不是"全部"——写成"全部区域"在部分筛选时就是在撒谎。

### 时间智能：一个机制，四个工厂

> **某个函数造出一张日期表 → `CALCULATE` 拿它当筛选器。**记住这条，十几个时间智能函数都是变体。

| 函数 | 造出什么 |
|---|---|
| `SAMEPERIODLASTYEAR ( d )` | 当前范围整体平移一年 ≡ `DATEADD ( d, -1, YEAR )` |
| `DATEADD ( d, n, 单位 )` | 通用版：DAY / MONTH / QUARTER / YEAR |
| `TOTALYTD ( 表达式, d )` | ≡ `CALCULATE ( 表达式, DATESYTD ( d ) )` |
| `DATESINPERIOD ( d, 起点, n, 单位 )` | 从起点往回/往前数 n 个单位的连续日期 |
| `CLOSINGBALANCEMONTH ( 表达式, d )` | ≡ `CALCULATE ( 表达式, ENDOFMONTH ( d ) )` ⚠️ 要求月末那天有数据 |
| `LASTNONBLANK ( 列, 表达式 )` | 从后往前第一个让表达式非空的值（单行表） |

**三条要求**（`dim_date` 为什么是整年 730 行 + Mark as date table）：日期连续无缺口、覆盖整年、已标记为日期表。
⚠️ **永远用 `dim_date[Date]`，不用 `fact_sales[sale_date]`**（有重复、有缺口）。
⚠️ **时间计算走真实日期列，不走数字月份**：`month − 1` 在 1 月变成 0；`DATEADD` 跨年是自然行为。
⭐ **时间智能函数当筛选参数时，清除整张日期表上的筛选**（不只是 `Date` 列）；**普通筛选器只清它点名的那一列**。

### 迭代器家族（`SUMX` / `AVERAGEX` / `MAXX` / `MINX`）

```dax
SUMX ( 要遍历的表 , 对每一行算什么 )
```

存在的理由：**DAX 的 `SUM` 只接受一列**，`SUM(a * b)` 写不出来。
⭐ **`AVERAGEX` 会跳过结果为空的行**——空月既不进分子也不进分母。
⚠️ `CALCULATETABLE` = **返回表的 `CALCULATE`**，筛选规则完全一样。

**"迭代器里用列不用度量值"的准确表述**：能用列解决就用列（性能）；**需要逐行重算一个度量值时，用度量值才是对的**（靠上下文转换）。

⭐ **要不要先清筛选？看你是"走出"当前格子还是"细分"当前格子**：
- 走出去（当前月 → 前三个月）→ 必须先清（`CALCULATE(…, Win)` 包在外面）
- 细分（当前月 → 这个月的每一天）→ 不用清

### 总计行不是上面各行的加总

度量值**没有"总计行"这个概念**，它只是在一个更宽的筛选上下文里又算了一次。

| 现象 | 原因 |
|---|---|
| 占比六行加起来 200%，总计显示 100% | 比率在总计行重算 |
| 总计行客户数 < 各行相加 | `DISTINCTCOUNT` 去重 |
| 总计行加权均价 ≠ 各行平均 | 总金额 ÷ 总吨数 ≠ 各行单价的平均 |

> 要让小计行显示"占全国"而不是 100%，得在度量值里判断当前在哪一层 → **`ISINSCOPE`**（下一节课）。

## 六、常见错法清单（不报错，但口径错）

> 模块 4 从 11-17 到 11-24 撞到的全部"看起来对、不报错、数字合理"的情况。**到岗后真正会出事的就是这一类。**

## 十、⭐ 度量值口径对照表

> **这张表是模块 4 真正的产出物。**它证明的不是"会写 DAX"，是"**知道同一个指标有几种口径、以及为什么**"。
> 读法：先看"回答什么问题"，再确认"在哪些层级有意义"。标 ⚠️ 的格子**算得对、但问题没意义**。

### A · 卖了多少

| 度量值 | 口径 | 月行 | 年度行 | 总计行 |
|---|---|---|---|---|
| `Total Amount` | 当前筛选下的金额 | 该月 ✅ | 该年 ✅ | 全部 ✅ |
| `Amount YTD` | 年初 → 当前期末 | 累计 ✅ | = 该年全部 ✅ | ⚠️ 取上下文里**最后一年**的 YTD，≠ `Total Amount` |
| `Amount R3M` | 近 3 个月合计 | ✅ | ⚠️ 无意义 | ⚠️ 无意义 |
| `Avg Monthly R3M` | 近 3 个月月均（**跳过空月**） | ✅ | 空（护栏） | 空 |

### B · 比过去怎么样

| 度量值 | 口径 | 月行 | 年度行 | 总计行 |
|---|---|---|---|---|
| `Amount LY` | 去年同期（整期平移） | 去年同月 ✅ | ⚠️ 去年**全年** | ⚠️ |
| `Amount LY (comparable)` | 去年同期，**截到去年的同一天** | 同上 ✅ | ✅ 2025 年 1–8 月 | ⚠️ |
| `YoY %` | (本期 − 去年) ÷ 去年 | ✅ | ⚠️ **−32.11%**（8 个月比 12 个月） | ⚠️ |
| **`YoY % (comparable)`** | 同上，分母用 comparable | ✅ | ✅ **+0.40%** | ⚠️ 关掉总计行 |
| `Amount PM` | 上个月 | ✅ | ⚠️ 整年往前挪一个月 | ⚠️ |
| `MoM %` | 环比 | ✅ | 空（`ISINSCOPE`） | 空 |
| `YoY % (YTD)` | YTD 同比 | ✅ | ⚠️ | ⚠️ |

> **同一个 2026 年 6 月**：单月 16.26 亿 / 同比 **+2.70%** / 环比 **+54.16%** / YTD **+2.96%** / 滚动月均 13.18 亿。
> **没有哪个是"对的那个"。**先问清楚对方要回答什么问题，再选口径。

### C · 占多少

| 度量值 | 分母是什么 | 一组加起来 |
|---|---|---|
| `Amount % of Total` | `ALL ( dim_customer )` → 当年全部客户 | 按年×类型六行 = **200%**（每年各 100%） |
| `Amount % of Grand Total` | `ALL ( dim_customer ), ALL ( dim_date )` → 固定 271 亿 | **100%** |
| `Amount % of Selection` | `ALLSELECTED ()` → 用户当前选择 | **100%** |
| `Amount % of Region` | `ALLEXCEPT ( dim_customer, region )` → 所在区域 | 区域内 100%；**区域行 100%** |
| `Amount % (hierarchy)` | 客户行占区域 / 区域行占全国 | 四个区域行加总 100% |
| `Amount % (hierarchy, selection)` | 同上，但"全国"跟着切片器走 | 选华东+华北 → 69.49 / 30.51 / **100%** |

> ⚠️ `Amount % of Total` 的名字不带口径（"Total" 指哪个 total？）——**待改名 `Amount % of Year`**。

### D · 平均与单位

| 度量值 | 分子 ÷ 分母 | 值 | 注意 |
|---|---|---|---|
| `Avg Price (weighted)` | 总金额 ÷ 总**湿**吨 | 2025 890.41 / 2026 941.10 | ⚠️ 铁矿石按**干吨**定价，严格说口径不对 |
| `Avg Credit Days (weighted)` | 元·天 ÷ **全部**金额 | **30.73** | 分母含 5,192 万无账期金额（按 0 天算） |
| `Avg Credit Days (terms only)` | 元·天 ÷ **有账期**金额 | **30.79** | 分子分母口径一致 |
| `Amount per Customer (identified)` | 总金额 ÷ 13 | 刘洋 450,103,673.45 | 分子仍含孤儿金额 |
| `Amount per Customer (identified, strict)` | 都排除 -1 | 刘洋 449,403,373.08 | ✅ 口径一致 |

> ⭐ **同一个"人均客户金额"写出过三张不同的销售员排名**，三个都不报错。见第六节。

### E · 库存（半可加）

| 度量值 | 口径 | 月行 | 年度行 | 总计行 |
|---|---|---|---|---|
| ⚠️ `Total Stock` | 直接 SUM | ❌ 同一批矿数 4–5 次 | ❌ | ❌ 比真实大 **88 倍** |
| ⚠️ `Closing Stock (CBM)` | **日历月末那一天** | ❌ 20 个月只命中 4 个 | ❌ 空 | ❌ 空 |
| **`Closing Stock`** | **最后一个有数据的日期** | ✅ 月末 | ✅ 年末 | ✅ 最新 |
| `Average Stock` | 期间内有快照的天数的平均 | ✅ 月均 | ✅ 年均 | ✅ 全期均值 |

### ⭐ 三条选用规则

1. **名字必须带口径。**后缀写清楚：`(weighted)` `(terms only)` `(identified)` `(comparable)` `(hierarchy)`。**绝不用版本号**（`_v2` / `2` / `new`）。
2. **指标里有没有写死的时间单位，决定了它能不能跨层级。**
   - `MoM %` 写死 `MONTH` → 只有月层有意义 → 必须加 `ISINSCOPE` 护栏
   - `Closing Stock` 没写死单位（"最后一个有数据的那天"）→ 月末/年末/最新都成立
   - **`CLOSINGBALANCEMONTH` 名字里就带着 MONTH**——名字已经告诉你它的适用层级
3. **同一个问题有几种口径时，那是业务问题不是技术问题。**`30.73` vs `30.79`、`−32.11%` vs `+0.40%`、三张销售员排名——**去问数据的主人**，在问清楚之前两个数都不该发出去。

## 十一、清理清单（DAX 学完时一起做）

| 动作 | 对象 | 理由 |
|---|---|---|
| 删 | `Amount per Customer`、`Amount per Customer (served)`、`Customer Count (served)`、`Amount per Customer (identified)` | 练习品。名字相近、口径不同的度量值并存 = 同事会随手拖错一个 |
| 留 | `Customer Count (identified)`、`Amount per Customer (identified, strict)` | |
| 二选一 | `Avg Credit Days (weighted)` vs `(terms only)` | **业务问题**，要去问数据主人 |
| 删 | `Steel Amount 2026` | 日期写死进度量值，不该留在正式模型 |
| 改名 | `Amount % of Total` → `Amount % of Year` | 名字要带口径 |
| 改 | `High Dry Price Amount` 里 `>=` → `>` | 题目是"大于 1000" |
| 清理写法 | 所有 `fact_sales[度量值名]` 的表名前缀 | 引用度量值 `[X]`，引用列 `表[列]` |
| 考虑 | `Avg Price (weighted)` 换成干吨口径 | 铁矿石定价按干吨 |
| 删 | `Amount 2026` | 写死年份的练习品，**11-24 已经被误用过一次** |
| 删 | `n Customers Visible`、`Has One Customer` | 11-22 的诊断用度量值 |
| 二选一 | `YoY %` vs `YoYVAR %` | 内容相同，后者是 `VAR` 重构版 |
| 二选一 | `Amount LY` vs `(comparable)`、`YoY %` vs `(comparable)` | **月行完全相同，只在年度行不同**。正式报表只留 comparable 版 |
| 二选一 | `Amount % (hierarchy)` vs `(hierarchy, selection)` | 业务问题：Total 行要"占全国"还是"占当前选择" |
| 留作反例 | `Closing Stock (CBM)` | 教学价值高（函数名合适 ≠ 适合你的数据粒度），但别让它出现在正式报表里 |

| 报表 | Matrix 的 **Grand total 关掉** | 跨两年的表，总计行的同比无意义 |
